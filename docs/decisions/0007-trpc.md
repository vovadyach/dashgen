# 7. tRPC between the React app and the backend

- **Status:** Accepted
- **Date:** 2026-10-29

## Context

The React app talks only to the backend, both are TypeScript in one workspace, and a question streams the agent's steps while it runs. The page needs typed calls, loading and error states, and a stream.

The options considered:

- **REST + Zod,** which the backend already has, with OpenAPI docs. Shared schemas type the payloads, but a small client must still match paths and methods by hand.
- **tRPC.** Calls are typed from the backend's router, with no client to write or generate. It integrates with TanStack Query and streams over SSE.
- **oRPC.** Like tRPC, with OpenAPI built in, but younger, with a smaller ecosystem.

A review pointed out, fairly, that REST would also work for an API this small. tRPC was chosen for typed calls without a hand-written client, for TanStack Query, and because it's common in TypeScript teams.

## Decision

tRPC 11 under `/api/trpc`, through its Fastify adapter, with `@trpc/tanstack-react-query` on the page.

- **`ask` is a mutation** that starts a run and returns its ID. **`run` is a subscription** that streams that run's events over SSE.
- They're separate because tRPC reconnects a dropped subscription by calling it again. If one call did both, a network blip would start, and pay for, a second run. With the split, a reconnect replays the missed events by ID and never starts work.
- Inputs use the Zod schemas from `@dashgen/contracts`. Errors carry our own codes through an error formatter.
- `GET /api/health` stays plain HTTP, for CloudFront, the load balancer and the offline banner.

## Consequences

- A renamed or changed procedure breaks the page's build, not the page at runtime.
- Batching can put several calls into one HTTP request, so the per-IP limit counts each `ask` in tRPC middleware.
- Errors during a run arrive as a stream event with HTTP 200, so tests must read the stream.
- Run events are kept in the backend's memory, which is one reason the backend runs as exactly one task until they move to shared storage.
- No OpenAPI docs for now. tRPC's official `@trpc/openapi` exists, but it's alpha and doesn't cover subscriptions.
